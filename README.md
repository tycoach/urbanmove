# UrbanMove Analytics — End-to-End Data Pipeline

---

## Overview

UrbanMove Analytics helps Lagos city planners understand public
transportation patterns by consolidating data from three independent
sources into a clean, queryable PostgreSQL database.

This project builds a modular ETL pipeline that:
- Ingests raw transportation data from CSV files
- Cleans and validates the data using pandas
- Loads clean records into PostgreSQL using psycopg2
- Automates daily runs using Apache Airflow
- Tracks every run in an audit log

## Datasets

Three synthetic datasets simulate real urban transportation sources:

| Dataset | Source | Rows | Quality Issues Injected |
|---------|--------|------|------------------------|
| `vehicle_locations.csv` | GPS transponders (every 3 min) | 212 | Null GPS, negative speed, duplicate packets, null status |
| `passenger_counts.csv` | Door sensors + manual entry | 150 | Null boarding count, load > capacity, negative alighted, string instead of int |
| `weather_conditions.csv` | Lagos monitoring stations | 100 | Null temperature, humidity > 100%, negative rainfall, null condition |

## Pipeline Flow

```
generate_data.py
      ↓
  data/raw/*.csv
      ↓
  extract.py      ← reads CSV into DataFrame
      ↓
  transform.py    ← cleans, fixes types, handles nulls
      ↓
  validate.py     ← quality gate — blocks load if checks fail
      ↓
  load.py         ← bulk inserts into PostgreSQL (idempotent)
      ↓
  audit.py        ← writes run summary to pipeline_audit_log
```

Rejected rows are never silently dropped — they are saved to
`data/rejected/` with a `_rejection_reason` column for review.

## Cleaning Rules Applied

### Vehicle Locations
| Issue | Rule |
|-------|------|
| Duplicate GPS packets | Drop duplicates on `(vehicle_id, timestamp)` |
| Missing coordinates | Drop row — cannot impute GPS position |
| Negative speed | Clip to 0 — sensor malfunction |
| Null status | Fill with `'unknown'` |
| Out-of-bounds coordinates | Drop row — outside Lagos bounding box |

### Passenger Counts
| Issue | Rule |
|-------|------|
| Null boarding count | Drop row — core metric, cannot impute |
| Boarded stored as string | Cast to numeric with `pd.to_numeric()` |
| Negative alighted count | Clip to 0 — data entry mistake |
| Load exceeds capacity | Cap at capacity — physically impossible |
| Missing occupancy rate | Compute: `(current_load / capacity) × 100` |

### Weather Conditions
| Issue | Rule |
|-------|------|
| Null temperature | Impute with column median — sparse data, dropping creates gaps |
| Humidity > 100% | Clip to 100 — sensor spike |
| Negative rainfall | Clip to 0 — sensor error |
| Null condition label | Fill with `'Unknown'` |

## Database Schema

```sql
vehicle_locations       GPS pings — UNIQUE(vehicle_id, timestamp)
passenger_counts        Stop events — UNIQUE(trip_id)
weather_conditions      Station readings — UNIQUE(reading_id)
pipeline_audit_log      Run history — one row per dataset per run
vw_ridership_by_route_hour   Analyst view — pre-joined for BI queries
```

## Getting Started

### Prerequisites
- Docker and Docker Compose installed
- Python 3.11+ (for local runs without Docker)

---

### Option A — Run with Docker (recommended)

**1. Clone and configure**
```bash
git clone <repo-url>
cd urbanmove
cp .env.example .env
```

**2. Generate a Fernet key  and secret key for Airflow**
```bash
python -c "
from cryptography.fernet import Fernet
import secrets
print('AIRFLOW_FERNET_KEY=' + Fernet.generate_key().decode())
print('AIRFLOW_SECRET_KEY=' + secrets.token_hex(32))
"
```
Paste the output into `.env` as `AIRFLOW_FERNET_KEY` AND `AIRFLOW_SECRET_KEY`.

**3. Start all services**
```bash
docker compose up --build
```

This starts:
| Service | URL | Credentials |
|---------|-----|-------------|
| Airflow UI | http://localhost:8080 | admin / admin |
| pgAdmin | http://localhost:5050 | admin@urbanmove.com / admin |
| PostgreSQL | localhost:5432 | see `.env` |

**4. Generate data and run the pipeline**
```bash
# Generate CSV files
docker compose run pipeline python scripts/generate_data.py

# Run the full ETL pipeline
docker compose run pipeline python pipeline/runner.py
```

**5. Trigger the DAG manually**

Open http://localhost:8080, find `urbanmove_daily_etl`, and click **Trigger DAG**.

---

### Option B — Run locally (no Docker)

**1. Install dependencies**
```bash
pip install -r requirements.txt
```

**2. Set environment variables**
```bash
cp .env.example .env
# Edit .env with your local PostgreSQL credentials
export $(cat .env | xargs)
```

**3. Create the database schema**
```bash
psql -U urbanmove -d urbanmove_db -f sql/schema.sql
```

**4. Generate data**
```bash
python scripts/generate_data.py
```

**5. Run the pipeline**
```bash
python pipeline/runner.py
```

## Airflow DAG

**DAG ID:** `urbanmove_daily_etl`
**Schedule:** Daily at 05:00 UTC (06:00 WAT)
**Retries:** 2 attempts, 5 minute delay

```
start
  ↓
generate_data
  ↓
┌─────────────────────────────────┐
│ etl_vehicle_locations           │
│ etl_passenger_counts            │  ← parallel
│ etl_weather_conditions          │
└─────────────────────────────────┘
  ↓
check_audit_log
  ↓
end
```

The three ETL tasks run in parallel. `check_audit_log` confirms
all three loaded successfully before marking the run complete.

## Monitoring

After every run, query the audit log to see what happened:

```sql
-- Latest run summary
SELECT
    run_id,
    dataset,
    rows_extracted,
    rows_rejected,
    rows_loaded,
    status,
    completed_at
FROM pipeline_audit_log
ORDER BY completed_at DESC;

-- Ridership by route and hour
SELECT * FROM vw_ridership_by_route_hour
WHERE route_id = 'Route_A';

-- Check rejected rows
-- (see data/rejected/ directory for CSV files with _rejection_reason column)
```
